# Library: classes, parts, packages, datasheets

Four `kind`s live under `library/<subdir>/*.yaml`. Use `fae schema <kind>` for the exact schema of
any of them before writing — the summaries below are a map, not the source of truth.

## `component_class` (`library/classes/`)

Electrical/logical vocabulary: which pin roles exist, which parameters are required, inheritable
rules (`extends`, **linear** inheritance, no multiple inheritance). Has no geometry and no MPN.

```yaml
kind: component_class
id: mcu.generic
pins: [{role: vdd}, {role: vss}]
params: {required: [vdd_range_v]}
```

## `component_part` (`library/parts/`)

A real catalog instance: MPN, `pinout` (role → physical pin), `package.ref` (points to a
`component_package`), `datasheet_ref` (points to a `datasheet_extract`). `id` is always
`lcsc:CXXXXX`.

Autogenerated as a *stub* by `fae catalog fetch <lcsc_id>` — fields not obtained from the API are
absent with `provenance: missing`. **Fill in `class`/`pinout` from the datasheet**, don't guess.

Note: this repository does not version vendor `parts/` data — records obtained via
`fae catalog fetch` live in the user's local cache, outside the repository. Individual projects
may keep their own `library/parts/` if they want to version curated descriptors.

## `component_package` (`library/packages/`) — families, not standalone geometries

A package name like "SOIC-8" doesn't identify a single geometry (3.9mm and 5.3mm bodies coexist
under the same name). That's why a `component_package` is a **family** with **variants**:

```yaml
kind: component_package
id: soic-8
variants:
  "4.9x3.9":
    default: true
    body: {width_mm: 4.9, height_mm: 3.9}
    footprint: {pads: [...]}
    provenance: {footprint: {source: datasheet, sha256: "...", timestamp: "..."}}
```

`ComponentPart.package.ref` refers to a package either by `family` (uses the `default` variant)
or `family:variant` (explicit, e.g. `soic-8:4.9x3.9`).

**Data precedence rule (always)**: `datasheet` > `easyeda_api`/web > estimate. Never overwrite a
variant whose `provenance.source` is `datasheet` or `user` — if it needs updating, create a
sibling variant and flag the conflict to the user, never replace it silently. `fae catalog fetch`
already applies this rule automatically; if you're hand-editing a package YAML, apply it manually
too.

## `datasheet_extract` (`library/datasheets/`)

Structured extraction from a PDF — see `datasheet-extraction.md` for the full workflow of how to
fill one in. A single file usually covers an entire MPN family (`mpn_family: [...]`), not just one
variant.

## Multiple libraries in the same project

```yaml
# intent.yaml
libraries:
  - ../my-shared-library
```

Precedence when resolving a duplicate `id` across libraries: project library > declared
`libraries:` > fairypcbot's own library. See `docs/library_repo.md` for the full layout and how to
share a library via git (clone/pull is manual — the framework does not manage git).

## Before creating a new class/part/package

First check whether something reusable already exists (`fae schema` doesn't list instances, but
`library/classes/`, `library/packages/` in the project and in declared libraries are worth
checking before duplicating).
